# Configurable Backend Service Window

## Purpose

Avijit Sahyog can run as a read-only client during a configured overnight window so the application does not generate unnecessary backend traffic when the platform is not intended to be used.

The default window is **9:00 PM to 8:00 AM local device time**.

## Behaviour

During the configured window:

- static/already available UI remains visible;
- a top notice explains the service window;
- taps are intercepted and show the localized service-unavailable message;
- requests made through the shared \`ApiClient\` are rejected before an HTTP request is sent;
- direct backend clients used for authentication resolution, analytics mirroring, client health telemetry and admin analytics/health are also gated;
- no new backend request is intentionally generated by the Flutter client.

The backend itself is not shut down by this feature. It is a client-side traffic reduction mechanism.

## Configuration

The values are embedded into Flutter builds using Dart defines:

- \`BACKEND_SERVICE_WINDOW_ENABLED\` — defaults to \`true\`
- \`BACKEND_SERVICE_WINDOW_START\` — \`HH:mm\`, defaults to \`21:00\`
- \`BACKEND_SERVICE_WINDOW_END\` — \`HH:mm\`, defaults to \`08:00\`

The Android release workflow reads these from GitHub repository configuration variables.

To disable the restriction for a build:

\`\`\`text
BACKEND_SERVICE_WINDOW_ENABLED=false
\`\`\`

Changing a repository variable affects the next build/deployment. It does not change an already-installed Flutter binary.

## Time zone

The window is evaluated using the device's local time. The same build therefore follows the local clock of the device running it.

## Database usage consideration

This feature can reduce Neon Postgres compute usage when application traffic is a significant source of database activity. Neon automatically suspends idle computes and resumes them when new connections arrive. The client-side gate makes the overnight period explicitly quiet from the Flutter application's perspective.

It is not a guarantee that the database will consume zero compute during the window. Background jobs, external requests, connection activity or other infrastructure can still wake the database. Neon recommends checking compute activity and connection patterns when a compute remains active unexpectedly.
